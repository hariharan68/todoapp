# API Reference

Base URL: `http://localhost:8000` (default, from `VITE_API_URL` / direct calls).
Interactive Swagger UI: `http://localhost:8000/docs` (auto-generated by FastAPI —
useful for trying requests live and always reflects the current code).

## Auth

All endpoints except `POST /auth/signup`, `POST /auth/login`, and `GET /health`
require a bearer token:

```
Authorization: Bearer <access_token>
```

Obtain a token from `/auth/signup` or `/auth/login`. Tokens are JWTs signed with
`SECRET_KEY` (HS256), valid for `ACCESS_TOKEN_EXPIRE_MINUTES` (default 10080 = 7 days).
An invalid, expired, or missing token on a protected route returns:

```json
401 { "detail": "Could not validate credentials" }
```

## Auth — `/auth`

### `POST /auth/signup`

Create a new account and receive a token.

**Request**
```json
{ "email": "user@example.com", "password": "at-least-6-chars" }
```
- `password`: 6–128 characters.

**Response `201`**
```json
{ "access_token": "<jwt>", "token_type": "bearer" }
```

**Errors**
- `400` — `{ "detail": "An account with this email already exists." }`
- `422` — invalid email format or password too short/long (Pydantic validation)

### `POST /auth/login`

**Request**
```json
{ "email": "user@example.com", "password": "..." }
```

**Response `200`** — same `Token` shape as signup.

**Errors**
- `401` — `{ "detail": "Incorrect email or password." }`

### `GET /auth/me`

Auth required.

**Response `200`**
```json
{ "id": "uuid", "email": "user@example.com" }
```

## Tasks — `/tasks`

All routes below require auth and are implicitly scoped to the current user — you can
never read, modify, or delete another user's tasks (attempting to gives a `404`, not a
`403`, so existence of other users' tasks is never leaked).

### `GET /tasks/`

List the current user's tasks, newest first (`created_at desc`).

**Query params**
- `completed` (optional `bool`) — filter to only completed (`true`) or only open
  (`false`) tasks. Omit for all.

**Response `200`** — `TaskOut[]` (see shape below).

### `POST /tasks/`

Create a task directly (no AI involved).

**Request** (`TaskCreate`)
```json
{
  "title": "Buy milk",
  "description": null,
  "due_date": null,
  "priority": "medium",
  "tags": null
}
```
- `title`: required, 1–500 chars.
- `priority`: one of `"low" | "medium" | "high"`, defaults to `"medium"`.
- `due_date`: ISO 8601 datetime string or `null`.
- `tags`: free-form comma-separated string or `null`.

**Response `201`** — the created `TaskOut`.

### `GET /tasks/{task_id}`

**Response `200`** — `TaskOut`.
**Errors** — `404` if not found or not owned by the current user.

### `PATCH /tasks/{task_id}`

Partial update — only fields present in the body are changed (`exclude_unset`).

**Request** (`TaskUpdate`, all fields optional)
```json
{ "completed": true }
```

**Response `200`** — the updated `TaskOut`.
**Errors** — `404` if not found/not owned.

### `DELETE /tasks/{task_id}`

**Response `204`** — no body.
**Errors** — `404` if not found/not owned.

### `TaskOut` shape (returned by all task endpoints)

```json
{
  "id": "uuid",
  "user_id": "uuid",
  "title": "string",
  "description": "string | null",
  "due_date": "ISO 8601 datetime | null",
  "priority": "low | medium | high",
  "ai_priority_score": "integer 0-100 | null",
  "completed": "boolean",
  "tags": "string | null",
  "created_at": "ISO 8601 datetime",
  "updated_at": "ISO 8601 datetime"
}
```

## AI: Parse — `/parse`

Both routes require a working `ANTHROPIC_API_KEY`; on any LLM/config failure they
return `502` rather than crashing.

### `POST /parse/preview`

Parse free text into a structured task **without saving it**.

**Request**
```json
{ "text": "Email the client the proposal by Friday 5pm - high priority" }
```

**Response `200`** (`ParsedTask`)
```json
{
  "title": "Email client the proposal",
  "description": null,
  "due_date": "2026-09-25T17:00:00-04:00",
  "priority": "high",
  "tags": null
}
```

**Errors** — `502` `{ "detail": "Failed to parse task text: <error>" }`

### `POST /parse/`

Parse free text **and persist** the resulting task for the current user.

**Request** — same as `/parse/preview`.

**Response `201`** — `TaskOut` (the newly created task).
**Errors** — same `502` shape as above.

## AI: Prioritize — `/prioritize`

### `POST /prioritize/`

Score all of the current user's **incomplete** tasks (0–100, weighing due date,
stated priority, and content), persist `ai_priority_score` on each, and return them
sorted by score descending.

No request body.

**Response `200`** — `TaskOut[]`, sorted by `ai_priority_score` descending
(un-scored tasks sort last). Returns `[]` immediately if there are no incomplete
tasks (no LLM call made).

**Errors** — `502` `{ "detail": "Failed to prioritize tasks: <error>" }`

## AI: Chat — `/chat`

### `POST /chat/`

Send one message to the task-management agent. **Conversation history is held
server-side** (keyed by user id) — send only the newest message, never the full
transcript.

**Request**
```json
{ "message": "Add a task to call the dentist tomorrow" }
```

**Response `200`**
```json
{ "reply": "Done! I've added \"Call the dentist\" for tomorrow." }
```

The agent may call tools that create/list/complete/delete tasks as a side effect of
answering — after calling this endpoint, refetch `/tasks/` to see any changes (the
frontend does this automatically via TanStack Query cache invalidation).

**Errors** — `502` `{ "detail": "Chat agent failed: <error>" }`

**Note**: conversation memory is in-process (`MemorySaver`) and resets if the backend
restarts — a message sent after a restart starts a fresh conversation even though the
`thread_id` (user id) is unchanged.
